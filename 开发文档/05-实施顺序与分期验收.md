## 4. 一期验收矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| K01 | 来源失效、未审核、地域不符 | 不进入确定性引用/渠道推荐 |
| K02 | 事件日期早于当前版本 | 正确选择历史资料或提示待核实 |
| C01 | 押金约定清晰 | 准确提取，不强造风险 |
| C02 | 扣款范围模糊 | 原文准确，给出核实与协商问题 |
| C03 | 只有合同片段 | 不断言整份合同缺失条款 |
| C04 | 原文含重复引句、否定语义 | 定位及语义不误判；不能判断时明确提示 |
| C05 | 模型返回不存在的条文/引句 | 拒绝不可信内容，不展示为合法结果 |
| D01 | 个人房东、未知到期条件 | 补问，不默认消费者渠道适用 |
| D02 | 经营性中介、服务收费争议 | 根据审核受理范围匹配，而非只看主体名称 |
| D03 | 已协商无果/渠道待处理 | 后续步骤区别于尚未行动 |
| D04 | 证据缺失/未知/不适用 | 清单按状态区分，不否定权利 |
| D05 | 援助资格不明 | 先核实，不承诺免费代理 |
| U01 | 空输入、超限、未知日期、未支持城市 | 字段提示/限制说明正确，输入保留 |
| U02 | 重复点击、请求失败、迟到响应 | 无自动重发与旧结果覆盖 |
| U03 | 手机、键盘、来源链接 | 核心流程可用，无敏感数据泄露 |
| S01 | 密钥/正文/上游异常 | 不进入构建产物或日志 |
| S02 | 真实站点同源接口与模型 | 一条代表性真实请求成功且有来源 |
| S03 | 限流/预算或身份额度控制 | 实际验证，不能只依赖前端按钮 |

验收数据使用合成或明确授权且脱敏材料。上述“预期”均为待验收，当前没有已通过项。

## 5. 二期进入与退出条件

进入：一期两个入口真实可用、资料可查、异常有提示、公开部署和成本保护完成。退出：每个新增场景具有对应资料、表单、证据、规则、模板和浏览器主流程验证；用户修正事实后重新计算全部依赖结果。

二期按场景垂直完成，推荐顺序：提前退租 → 维修责任 → 额外费用 → 中介服务。可根据资料质量调整，不能只做四个入口而共享一套押金答案。

## 6. 三期进入与退出条件

| 能力 | 进入条件 | 退出条件 |
| --- | --- | --- |
| PDF文本输入 | 一、二期稳定 | 文本提取、校对、原分析接口贯通 |
| OCR | 真实服务/数据策略/函数限制已核实 | 图片和扫描PDF真实识别，金额可校正，失败不伪装成功 |
| 混合检索 | 足够的审核资料、基线评测和服务可用性结论 | 召回评测、地域/时间过滤、引用闭合及索引回滚通过 |
| 临时文件存储 | 同步无存储方案确实不满足需求 | 所有权、真实大小校验、受限访问及清理可验证 |
| Python服务 | 复杂处理证明必要且有部署资源 | 服务认证、任务生命周期、故障边界及外部部署适用性明确 |
| 材料导出 | 当前结果结构稳定 | 导出与界面一致，含版本/日期，不虚构事实 |

不能为了“技术栈丰富”添加服务。低资料量时，元数据筛选可能比向量检索更有效；三期评测没有证明收益时保留原方案。

## 7. 评测与实际结果记录方式

实现后为每次验收记录：编号、代码/资料版本、环境（夹具/本地真实依赖/已发布）、输入样例ID、预期、实测、通过/失败/未执行、限制。开发阶段可在任务记录维护；需要提交报告时再建立实际结果文件，不预填通过。

一期建议准备约12份合成合同样例、12组纠纷事实，覆盖表中关键分支；数量是启动基线，不表示足够证明法律准确率。规则适用、引用闭合和身份相关分支必须全部通过。法律解释需人工对照来源检查，模型自评不能代替审核。

浏览器验证与直接API测试分别记录。前端构建通过不代表Function可用，API返回200不代表法律结论正确，发布预览打开不代表模型调用成功。
