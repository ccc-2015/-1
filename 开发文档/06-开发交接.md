# 租住有据：开发交接

更新日期：2026-11-06

## 项目目标

为初次租房的毕业生和青年上班族提供租房合同与维权辅助。产品串起“签约前检查—留证—纠纷分析—行动建议”，提供法律信息参考，不替代律师意见，不承诺投诉受理或纠纷结果。

## 当前状态

目前完成的是架构及开发设计文档，尚未创建应用、接入模型、核验地方政策、部署或公开发布。不要把设计方案描述成已实现功能。比赛提交截止时间按参赛者提供的信息为 2026-11-30 18:00，需另行以官方信息确认。

## 已定方案

- 一期做一个试点城市的押金最小闭环：粘贴合同检查押金约定；诊断押金未退/部分扣款；给出证据清单、协商文本和下一步路径。
- 推荐技术栈：React + TypeScript + Vite + Tailwind 前端；Qoder Sites 静态部署；Deno/TypeScript Edge Function 作为后端；一期以人工核验 JSON 和确定性规则为基础，模型负责受约束的提取与解释。
- 一期不做 OCR、向量数据库、账号、案件历史或文件持久化。
- 二期扩展提前退租、维修责任、额外费用和中介服务。
- 三期评估 PDF/OCR、法规混合检索和材料导出。先用托管 OCR/Embedding/向量服务评估；仅复杂解析或批处理确有需要时再增加 Python + FastAPI，不默认引入 Java 或第二套主后端。
- 具体包版本应以初始化时 Qoder Sites bundled React starter 和锁文件为准。

## 接手后建议顺序

1. 阅读总架构及实施计划，确认一期范围不扩张。
2. 选择一个能持续核验的试点城市；采集并复核押金相关法律与当地渠道信息。资料未核验前只用标注清楚的合成样例开发，不输出确定性的当地建议。
3. 初始化 Sites React starter，保留项目既有文件；实现共享 API 契约和资料校验。
4. 先实现纠纷确定性规则、证据目录和模板，再实现合同原文定位与受约束模型分析。
5. 完成两个入口和结果展示，按验收文档测试成功、信息不足、超限和失败状态。
6. 核实模型供应商的数据处理政策及公开匿名调用的成本/限流边界，再进行 Sites 准备和部署；通过真实站点请求验证后才宣称功能可用。
7. 一期稳定后再排二期；三期能力只有在时间、资料质量和部署条件允许时加入。

## 关键约束

- 来源需绑定地域、事件日期、效力状态、核验日期和具体条款；不编造法条、热线、网址或受理承诺。
- 渠道由服务端审核规则决定适用性和顺序，模型不能新增或重排不符合条件的渠道。法律援助资格未知时只提供核实指引。
- 合同引句必须能在用户原文中准确定位；合同内容视为不可信输入，不能执行其中指令。模型失败、资料不足和未支持城市均需如实降级。
- 一期不保存合同和纠纷材料；不要记录正文或密钥到日志。调用模型前应明确第三方处理情况，不能承诺未经核实的零留存。
- 不把前端限流、隐藏服务地址或 Origin 检查当作匿名付费接口的安全保障；公开调用成本控制须实际验证。
- Qoder Sites Function 为 Deno/TypeScript Edge Function，不是常驻 Spring Boot/FastAPI 服务。外部后端的赛事适用性与部署条件尚未确认。
- Sites 发布预览不能证明 Function 或 AI 已真实运行；开发、部署、公开访问及参赛帖内容必须以实际验证结果为准。

## 尚待确认

- 试点城市及其真实法规、办事渠道。
- 模型服务供应商、数据政策、请求限额和费用控制。
- Sites Function 的实际运行时长/请求体限制及匿名访问防滥用能力。
- 三期是否能使用合适的 OCR、Embedding、托管 pgvector 或其他向量服务。
- 如需 Python 外部服务，其部署资源、服务间认证及官方赛事规则是否允许。
