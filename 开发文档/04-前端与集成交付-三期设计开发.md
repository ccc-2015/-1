# M4 前端与集成交付：三期设计开发

依赖：00—03。技术基线：React、TypeScript、Vite、Tailwind、React Hook Form、Zod，复用 Sites starter 的可访问UI组件。本文只定义实现，不代表已经创建项目或部署。

## 1. 一期：两个入口、一套结果体验

### 1.1 信息架构

采用单页应用和视图状态切换，无需安装路由库。主界面直接显示“检查押金条款”和“处理押金纠纷”两种入口，不先展示营销落地页。来源与处理说明使用抽屉/对话框，避免增加独立业务路由。

| 视图 | 内容 | 主要操作 |
| --- | --- | --- |
| 合同检查表单 | 城市、拟签约/签约日期、全文/片段、合同输入 | 填入示例、提交分析 |
| 合同结果 | 四类检查项、原文高亮、需确认问题、引用 | 定位原文、查看来源、复制建议 |
| 纠纷表单 | 对方身份、押金/争议额、退租交接、证据与已有行动 | 填入示例、生成方案 |
| 纠纷结果 | 事实摘要、证据缺项、协商文本、路径与条件 | 修改事实、复制文本、查看后续 |
| 来源详情 | 标题、条文、地域、效力说明、核验时间 | 打开核验过的官方来源 |
| 服务说明 | 支持范围、第三方处理、保存方式、使用边界 | 返回工作区 |

### 1.2 组件划分

```text
App / WorkspaceTabs
  CoverageNotice / PrivacyNotice
  ContractForm / ContractResult / SourceExcerpt
  DisputeForm / EvidenceChecklist / DisputePlan
  CommunicationEditor / ActionStep
  SourceSheet / RequestStatus
```

复用现有 tabs、sheet、dialog、alert、form、button、sonner；只按实际UI需要引入。优先语义 HTML，不为两个视图引入全局状态管理库或大型路由依赖。

### 1.3 状态模型

`idle → validating → submitting → success | partial | error`。partial 对应 limited/unsupported 或明确的能力降级；界面不能将它显示成“已全面审查”。

- 合同原文、纠纷信息、结果仅放 React 内存状态。
- 所有POST由用户主动提交；不随输入自动调用模型。
- 请求中禁用重复提交并显示明确状态；允许修改时取消旧客户端请求并忽略迟到响应。
- 客户端取消不代表供应商取消或费用撤回，界面不作此承诺。
- 修改输入后标记旧结果已过期，用户重新提交后替换；不在旧报告上静默更新局部字段。
- 切换入口保留本会话草稿；替换示例或重置有未提交内容时提示确认。
- 不用 URL query、localStorage、sessionStorage 保存合同、纠纷事实和结果；可保存纯主题偏好。

### 1.4 API 客户端

统一同源 `/functions/v1/app?action=...`，遵循00中的 envelope。GET config/sources 与 POST 两业务接口分别处理。拒绝将登录HTML、未知响应和原始上游错误当作结果展示。

前后端都校验请求。响应也校验，最少覆盖 ok/data/meta、业务必填字段、枚举及引用结构。前端只渲染通过校验的结果；生产错误展示稳定文案和 requestId，不返回供应商原始响应。

401提示按支持的站点身份入口登录，403说明无权限，429提示稍后手动重试，503/504保留输入。错误状态不自动重新POST。未配置模型时，样例模式必须显著标“示例结果”，不能让样例响应经过真实接口伪装分析成功。

### 1.5 表单规则

- config 决定支持城市和场景，不在前端硬编码成全国支持。
- 金额输入元，提交时严格解析为整数分；拒绝科学计数、超过两位小数、非有限数及超出安全整数的值，不用 parseFloat 后静默四舍五入。
- 日期可选择未知，不用当前日期自动补齐历史事件。
- 证据每项允许 available/missing/unknown/not_applicable，默认 unknown。
- 使用 fieldset/legend 分组；字段错误靠近输入，提交失败聚焦首个错误。
- 文本字符数与后端同用UTF-16计数，超限提示选择相关片段，不静默截断。

### 1.6 结果表达

合同按检查项目分组，优先级使用文字+图标而非仅颜色。高亮先验证后端偏移，对无法定位的内容显示“需核对原文”，不制造引用。原文通过普通文本节点渲染，不使用 dangerouslySetInnerHTML。

纠纷结果先显示仍需确认的事实，再显示当前可执行步骤；待核实渠道单独展示。未填写的模板占位符保留醒目标记，复制前提醒核对。一般协商建议与有来源的法律说明视觉上区分，但不堆叠重复免责声明。

来源链接仅取后端审核字段，校验为允许的HTTPS来源；外部新窗口使用 rel=noopener noreferrer。页面不将模型输出当HTML执行，不加载模型提供的图片或跳转地址。

### 1.7 示例体验

使用脱敏合成合同、合成纠纷事实，不使用真实用户材料。样例有两种明确状态：

1. “填入示例”：填表后走真实接口，结果可能受当前服务状态影响。
2. “查看示例结果”：读取固定展示夹具，标注不代表本次真实分析。

部署包中的示例不得含任何真实姓名、证件、账号或未授权合同。评委应能免登录体验固定示例；真实付费接口的匿名防滥用能力按00中上线条件验证。

## 2. 一期部署与集成

### 2.1 初始化与本地联调

使用 Sites bundled React starter 在原工作区初始化，先确认现有文档不被覆盖；如初始化器拒绝非空目录，采用经过检查的合并方式或在原工作区明确的应用子目录初始化，不删除文档。保留模板包管理器和锁文件。

前端 Vite，函数 Deno，开发代理 `/functions/v1/app` 指向本地函数。Function import使用显式相对扩展名，不假定前端别名可在Deno解析。开发替身放dev/tests，不放入生产function目录。

### 2.2 构建与发布流程

1. 校验资料快照和场景引用，生成只读TS数据。
2. 运行前端类型检查和构建，确认静态输出含index.html。
3. Deno检查实际生产入口和所有导入；Deno不可用时明确此检查待完成，不能用前端tsc代替。
4. 本地浏览器完成主流程及输入边界检查。
5. 按Sites正式流程准备静态目录和app函数目录，Secret只声明名称。
6. 验证后端就绪、Secret同步和匿名用量控制，再发布公开作品。
7. 从真实站点调用一次代表性分析，核实Function、模型和资料实际连通。

工具生成的站点描述文件不手写、不修改；静态发布预览不能执行Function，不能据此认定AI功能已上线。

### 2.3 超时与观测

初始建议：模型请求超时25秒、函数业务截止30秒、客户端等待35秒；部署前必须根据平台实际限制缩短并留余量。这些值是待验证应用配置，不保证平台执行窗口。不要用多个完整串行模型请求突破总预算。

日志允许字段：requestId、action、状态、耗时、knowledgeVersion、processingMode、固定错误码、去标识的供应商请求耗时。禁止合同正文、纠纷叙述、模板内容、密钥、完整上游错误、用户文件、签名链接进入日志。不要在URL中提交这些内容。

用量保护在服务端/供应商层验证。Origin检查和隐藏后端地址都不是鉴权。服务间调用若后续增加，需要可信认证并防止绕过网关的公开付费端点。

### 2.4 一期浏览器验收

- 示例填入→真实合同分析→原文定位→来源查看→复制建议。
- 押金纠纷表单→证据缺项→模板编辑→路径及后续分支。
- 空输入、超限、未知日期、未支持城市、缺失资料、超时、重复点击。
- 360px级手机宽度及桌面无水平溢出，键盘能完成核心流程，焦点顺序清晰。
- 监控控制台/网络错误，源码和构建产物无服务密钥。

## 3. 二期：多场景交互与事实校正

不增加新的后端体系。场景入口由 config 驱动，表单按判别联合结构渲染。只展示当前可用场景，切换时保留可复用的已确认事实，不复用不相关结论。

新增事实校对区：显示“合同识别值”和“用户修正值”，记录来源；点击重新分析才更新报告。与纠纷模块联动时只传确认字段，不把完整合同默认带入其他流程。

留证页按签约/入住/居住/退租显示适用项目，可勾选本会话状态，仍不上传保存证据。页面文案明确“清单”，不能标为“证据已安全备份”。

验收：全部新增场景从入口到结果可用；合同修正后旧结果标为过期；返回修改不丢当前会话输入；无关旧字段不影响新场景。

## 4. 三期：文件输入、导出与可用性

### 4.1 文件输入及校对

文件默认只保存在本设备内存，文字PDF优先本地提取，扫描件说明第三方OCR并取得明确提交操作。只发到固定后端接口，不接受用户自定义OCR地址。PDF解析关闭不需要的脚本/附件执行能力，不把文档作为HTML嵌入。

展示每页提取文字和质量提示，用户可编辑。必须点击“确认文本并分析”才进入M2。清空文件时释放对象URL及渲染资源；超页/超字数提供选择页面或粘贴片段方式，不能隐藏截断。

只有确需临时存储时才启用Sites Storage或外部私有存储：先建立可靠身份/任务所有权、受限上传和真实删除机制。产品目标为任务结束后删除且最长24小时清理，必须通过实际定时任务与删除验收才可宣传；默认无存储则不声明已存在定期清理。陌生浏览器传来的ownerId或随机jobId不足以证明权限。

### 4.2 材料导出

先采用浏览器纯文本下载和打印样式，PDF可通过浏览器“打印为PDF”，不增加服务端PDF渲染。导出事实摘要、证据状态、协商文本、当前路径、资料版本、来源核验日期和生成时间；不包含用户未选择公开的合同全文。文件名不含姓名、完整地址或证件信息。

### 4.3 可用性完善

完善读屏标签、键盘操作、文字缩放、清晰对比度、状态播报和打印布局。仅在用户可见的当前草稿保留材料，导出前提供预览。复杂案件不确定性仍显示，不以界面美化隐藏覆盖不足。

### 4.4 验收

真实OCR调用和文件识别结果可追溯；本地文本提取与云OCR模式能区分；识别纠错后传入相同合同分析接口。导出结果与界面当前版本一致。无法验证文件隔离或清理时，不上线托管存储分支。

## 5. 与其他模块的接口检查

- config 的 features/limits 与实际服务端校验一致。
- findings原文偏移与前端JavaScript字符串约定一致。
- 所有 sourceRefs 均有响应内 references，可离线完成当前结果展示。
- 每条 unresolvedStepIds 指向当前 nextSteps/conditionalOptions 中的现有步骤。
- 业务错误、能力不足和示例状态分别展示，不将三者合成一个“成功”提示。
